# Задание Т1. Сравнительный анализ генераторов статических сайтов

Для анализа выбраны 4 генератора:
1. **MkDocs** (с темой оформления **Material for MkDocs**) — компонентно-ориентированный SSG на Python, ориентированный на техническую документацию.
2. **Sphinx** (с парсером **MyST-Parser**) — классический отраслевой стандарт документирования Python-проектов с расширенной поддержкой разметки Markdown.
3. **Pelican** —  SSG на Python с архитектурой, ориентированной на блоги и контентные сайты.
4. **Quarto** — современная научно-издательская система нового поколения, разработанная специально для Data Science и научной коммуникации.

---

Для публикации результатов экспериментов критерии имеют неравную значимость. Введена 5-балльная шкала весов ($W \in [1; 5]$):

* **Представление научного контента (Вес: 5):** Исследование невозможно опубликовать без формул LaTeX, автонумерации уравнений, перекрёстных ссылок на литературу (BibTeX) и вставки графиков.
* **Экспорт в полиграфические форматы (PDF/LaTeX) (Вес: 4):** Научный результат должен существовать в концепции единого источника  — из одного `.md` или `.qmd` файла должна генерироваться как веб-страница, так и рецензируемый preprint/PDF для печати.
* **Качество поиска по русскоязычным текстам (Вес: 4):** Большие исследовательские отчёты требуют быстрого полнотекстового поиска с учётом русской морфологии.
* **Многоколоночная вёрстка и мобильная адаптивность (Вес: 4):** Графики и таблицы требуют гибких сеток, читаемых со смартфонов и планшетов.
* **Скорость холодной и инкрементальной сборки (Вес: 3):** Большие ноутбуки с вычислениями не должны пересчитываться часами при каждой правке опечатки.
* **Автодокументирование docstrings (Вес: 3):** Актуально, если к отчёту прикладывается исходный код вычислительной модели.

Для предметной области "Программная инженерия" наиболее оптимальным генератором будет являться MkDocs (Materials). Он имеет встроенную поддержку диаграмм Mermaid, построчные аннотации к листингам кода, табы для переключения языков/ОС и автогенерацию API-документации через `mkdocstrings`. Также он использует чистый Python-стек, что дает высокую скорость сборки. Есть полнотекстовый поиск с морфологией русского языка, работающий оффлайн.

### Граничные условия смены стека
* Сдача cтатьи в академический журнал (IEEE, ВАК): Для таких случаев лучше подойдут Sphinx, Quarto, так как они умеют верстать двухколоночные тексты со структурой BibTex.
* Тяжелые вычисления на сайте: Лучше использовать Quarto, так как он позволяет выполнять вычисления при сброке и кэшировать их через `freeze`.
